# Resend transactional email setup

The student email campaigns use Resend from the server. The application never exposes the Resend API key to the browser.

## 1. Verify the sending subdomain

1. Create or sign in to a Resend account.
2. In **Domains**, add `notify.evoluirmaisenglishai.com`.
3. Copy the DNS records Resend generates for that domain.
4. In Wix, open **Domains → evoluirmaisenglishai.com → Manage DNS Records**.
5. Add the records exactly as Resend displays them. Use the Wix-supported TXT, MX, and CNAME record sections. Do not replace the domain's Wix nameservers.
6. Return to Resend and verify the domain. Wait until its status is **Verified**.

Do not reuse the DNS values generated by Lovable. Resend generates its own SPF/DKIM/return-path records.

## 2. Configure application secrets

In Lovable Cloud, add these server-side secrets/environment variables:

- `RESEND_API_KEY`: required; create a Resend API key with sending access for the verified domain.
- `RESEND_FROM_EMAIL`: optional; accepts either a bare email address or a complete sender such as `Evoluir+ English AI <noreply@notify.evoluirmaisenglishai.com>`; defaults to `noreply@notify.evoluirmaisenglishai.com` with the application sender name.
- `RESEND_REPLY_TO`: optional; set this to the owner's Hotmail address if replies should go there.

Never add `RESEND_API_KEY` to a `VITE_*` variable or client-side code.

## 3. Test

After the domain is verified and the secret is saved, deploy the application and send a test welcome email to an address controlled by the administrator. Confirm delivery and reply-to behavior before using campaigns for students.

## Delivery and retries

The application continues to persist campaign status in `email_campaign_deliveries`. It sends the existing stable campaign idempotency key to Resend using the `Idempotency-Key` header. Resend retains idempotency keys for 24 hours; the application's persistent delivery record remains the longer-lived campaign history.
